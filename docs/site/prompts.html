ReaPlus Prompt Kütüphanesi (10 hazır prompt)

Ajanın rea-plus'a soracağı 10 hazır soru kalıbı. Her prompt: Amaç + Örnek çağrı (gerçek MCP/rea-plus-cli formu, alan adları üretilmiş referans TOOLS.md ile aynı) + Beklenen çıktı türü. Yüzey: 187 araç, 183 outputSchema, 187 annotations, 2 resource, 3 prompt.

Not: confirm:true isteyen canlı-debug çağrıları listede yok; buradaki 10 promptun tamamı salt-okunur/statik akışlardır.

1) Triage — "bu dosya nedir, nereden başlarım?"

Amaç: Bilinmeyen bir dosyayı tek çağrıda sınıfla ve sonraki adım planını al.

Örnek çağrı:

{ "name": "rea_investigate", "arguments": { "path": "sample.exe" } }

Beklenen çıktı: ok/plan/skor/tip/motor/yedekler alanlı nesne (outputSchema alanları: arac, motor, ok, plan, skor, tip, yedekler); tip (pe/elf/apk/…), güven skoru ve önerilen motor + yedek plan listesi.

2) Manifest — "bu APK'nın paketi, izinleri, aktiviteleri?"

Amaç: APK'nın AndroidManifest.xml kimliğini jadx ile çöz.

Örnek çağrı:

node -e "import('./dist/rea-domains/android/JadxBridge.js').then(m=>console.log(JSON.stringify(m.rea_jadx_manifest('tests/corpus/sahte.apk'))))"

Beklenen çıktı: ok/paket/izinler/aktiviteler alanlı nesne; jadx yoksa uydurma manifest yerine capability_unsupported + kurulum ipucu.

3) Davranış — "olayları zaman çizgisine diz"

Amaç: API/syscall/net/dosya/process olaylarından kaynak-öncelikli özet üret (yürütme yok, saf fonksiyon).

Örnek çağrı:

node -e "import('./dist/rea-domains/behavior/BehaviorTimeline.js').then(m=>console.log(m.rea_behavior_timeline([
 {\"kaynak\":\"api\",\"zaman\":3,\"detay\":\"CreateFileW\"},
 {\"kaynak\":\"net\",\"zaman\":1,\"detay\":\"dns:ornek.test\"},
 {\"kaynak\":\"api\",\"zaman\":2,\"detay\":\"CreateFileW\"},
 {\"kaynak\":\"process\",\"zaman\":4,\"detay\":\"exit:0\"}
]).summary))"

Beklenen çıktı: Metin özet (4 olay api@2 -> process@4 top_api=CreateFileW biçimi) + sıralı/sayılar/top_api/ilk/son detayları; boş listede capability_unsupported.

4) Repo — "bu dizinde ne tür dosyalar var?"

Amaç: Bir dizindeki PE/ELF/APK/JS/WASM dosyalarını sihir baytla tespit edip dosya başına sonraki-araç planı al.

Örnek çağrı:

{ "name": "rea_scan_repo", "arguments": { "path": "<hedef-dizin>" } }

Beklenen çıktı: summary metni (5 dosya, 5 tip … biçimi) + details.tipler sayımı + details.planlar (dosya → önerilen motor); hedefsiz dizinde boş liste (ok:true).

5) PDB — "debug kaydından sembole git"

Amaç: PE'nin CodeView RSDS kaydından PDB kimliğini çöz, Microsoft symbol server düzeninde indir (bütünlüklü + önbellekli).

Örnek çağrı:

node -e "import('./dist/rea-domains/typedef/PdbReader.js').then(m=>console.log(JSON.stringify(m.rea_pdb_yolu('<debug-bilgili.exe>'))))"

Beklenen çıktı: Adım 1'de pdb/guid/yas (rea_pdb_yolu alanları: arac, dosya, guid, ok, pdb, yas); adım 2'de Ad/GUID-tiresiz+YAŞ/Ad düzenli URL, yol/cache bilgisi (rea_pdb_indir alanları: arac, cache, dosya, guid, ok, pdb, url, yas, yol); bozuk içerikte butunluk_hatasi, ikinci çağrıda cache:true.

6) Diff — "iki sürüm arasında fonksiyon farkı ne?"

Amaç: İki ikili sürümün fonksiyon listelerini karşılaştırıp eklenen/çıkarılan/değişen/aynen kalan kümeleri al (N-day incelemesi girişi).

Örnek çağrı:

{ "name": "rea_bindiff_karsilastir", "arguments": { "text": "<rea_bindiff_fonksiyonlar çıktısı>" } }

Beklenen çıktı: aynen/cikarilan/degisen/eklenen/eski/yeni/istatistik/ozet alanlı nesne; girdi rea_bindiff_fonksiyonlar (path zorunlu) çıktısıdır.

7) Pcap — "bu yakalamada hangi akışlar var, TLS çözülür mü?"

Amaç: PCAP dosyasındaki akışları birleştir; keylog varsa TLS içeriğini çöz.

Örnek çağrı:

{ "name": "rea_pcap_oku", "arguments": { "path": "ornek.pcap" } }

Keylog ile:

{ "name": "rea_pcap_oku", "arguments": { "path": "ornek.pcap", "keylog": "sslkeylog.txt" } }

Beklenen çıktı: details/summary içinde birleştirilmiş akış listesi (outputSchema var); keylog opsiyoneldir, verilmezse şifreli içerik çözülmeden meta-akışlar döner.

8) Reçete — "bu APK için dinamik analiz planı üret ve doğrula"

Amaç: APK yolundan kuru-doğrulamalı dinamik analiz reçetesi üret (çalıştırma yok, plan + doğrulama).

Örnek çağrı:

{ "name": "rea_android_dinamik_recete", "arguments": { "path": "ornek.apk" } }

Ardından reçete metniyle:

{ "name": "rea_android_recete_dogrula", "arguments": { "text": "<recete-metni>" } }

Beklenen çıktı: İlki recete alanlı nesne; ikincisi adim_sayisi/ok alanlı doğrulama sonucu.

9) Fuzz — "ayrıştırıcılar bozuk girdide çökmüyor mu?"

Amaç: PE/ELF/WASM/metadata ayrıştırıcılarına korpus tohumlarıyla bozuk girdi verip çökme/istisna taraması yap (yazma yalnız tmpdir'e).

Örnek çağrı:

node scripts/fuzz-parsers.mjs

Beklenen çıktı: Konsol özeti (tohum sayısı, çöken girdi listesi; temiz koşuda sıfır çökme) + tests/parser-fuzz.test.mjs yeşili; korpus (tests/corpus/) salt okunur kalır.

10) Perf — "liste/açılış bütçeleri tutuyor mu?"

Amaç: tools/list yanıt süresi + sunucu açılış süresi bütçelerini ölç, regresyonu testle yakala.

Örnek çağrı:

node tests/perf-budget.test.mjs

Beklenen çıktı: node:test çıktısı (bütçe eşikleri tests/perf-budget.test.mjs içinde tanımlı); eşik aşımı testi kırmızıya düşürür, süreler konsolda milisaniye olarak raporlanır.
